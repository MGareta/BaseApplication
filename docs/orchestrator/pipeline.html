Orchestrator pipeline: OpenSpec feature delivery

One OpenSpec change per feature (add-<feature>-feature), run by the openspec-feature workflow in three stages. Each phase ends at a mechanical + judged gate. Fix loops are bounded, and anything beyond a limit stops for a human. Every phase must follow its openwiki/ module wiki (HOW to build); the OpenSpec change says WHAT to build. Hover or focus a step for details.

Escalation. Any loop over its limit, a spec-attributed failure, a core-change request, or a failed preflight stops the run and returns to the human. Progress is kept in the checked tasks.md boxes and .orchestrator/verdicts/.
Guardrails. PreToolUse hook (scripts/orchestrator/guard-paths.sh) blocks edits to core/**, openwiki/**, openspec/specs/**, git push, and openspec archive without approval, but only while a run is active.
